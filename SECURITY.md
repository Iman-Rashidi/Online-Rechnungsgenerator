# Security Policy

## Supported versions

Security fixes are provided for the latest version available on the repository's `main` branch. Older versions may not receive security updates.

## Reporting a vulnerability

Please do **not** report security vulnerabilities in public GitHub Issues or Pull Requests.

Instead, use GitHub's private vulnerability reporting feature, if it is enabled for this repository:

1. Open the repository's **Security** tab.
2. Select **Report a vulnerability** under **Advisories**.
3. Provide a clear description, the potential impact, and steps to reproduce the issue.
4. Include only the minimum information needed to explain the report.

If private vulnerability reporting is unavailable, contact the repository maintainer privately through the contact method listed on the maintainer's GitHub profile. Do not publish exploit details before the maintainer has had a reasonable opportunity to investigate and prepare a fix.

## What to include

- Affected component and version or commit.
- Impact and realistic attack scenario.
- Steps to reproduce, proof-of-concept, or relevant logs, where safe.
- Any suggested mitigation.

## Protect sensitive information

- Never include real customer invoices, personal data, bank details, passwords, API keys, Telegram bot tokens, or MCP access tokens in public reports.
- Do not attempt to access, modify, or delete data that does not belong to you.
- Test only systems and accounts you own or have explicit permission to assess.
- Redact secrets and personal information from screenshots, logs, and example requests.

## Response expectations

The maintainer will review reports as time and availability allow. Please include a way to request clarification through GitHub's private reporting flow. There is no guaranteed response or fix timeline.

Thank you for helping keep Rechnio and its users safer.
